fix: the primary button label vanished on hover - a CSS specificity trap

Hussein reported "اقرأ قصتي" disappearing on hover and sent screenshots.
My first fix was wrong: I assumed a ::after gleam overlay was painting over
the text and moved it to a background layer. The overlay was a real defect,
but not this one. The bug survived that change.

The actual cause was in the base stylesheet:

  a:hover          { color: var(--gold) }   specificity (0,1,1)
  .btn-primary    { color: var(--void) }   specificity (0,1,0)  LOSES

On hover the label turned gold, on top of a bright violet-gold spectrum, and
disappeared. Confirmed in the live page: getComputedStyle reads rgb(4,5,10) at
rest, and forcing the pre-fix colour with !important gives rgb(240,206,126) -
exactly the gold that vanished.

Also avoids a tie rather than relying on source order: a.btn:hover and
a.btn-primary:hover are both (0,2,1). The light buttons now use
a.btn:not(.btn-primary):hover and the primary uses a.btn-primary.btn:hover
(0,3,1), so the two can never compete.

All link label colours now live in one block in site.css section 7, type-
qualified so they outrank the bare a:hover.

New tools, because "I looked" is not a check:

- tools/hover-colour-audit.js - computes browser precedence statically and
  fails if any coloured link does not re-state its colour on hover.
- tools/css-parse-check.js - brace balance, top-level rule count, and var()
  calls to tokens that do not exist. A CSS syntax error makes the parser drop
  every rule after it silently.
- tools/check.js - runs all four static checks in one command.
- The browser harness gained a live CSSOM version of the hover check, plus
  probeOne() for single-case checks without waiting for all 63.

Two things I got wrong in my own tooling, both now fixed and documented:

1. The browser hover audit read 0 rules and reported "clean" for several
   rounds. Array.prototype.slice.call() on a CSSRuleList, and testing
   rule.cssRules alone (style rules can expose an empty-but-present
   cssRules), both sent the walk down a dead branch. It now indexes
   explicitly, keys on selectorText, and fails loudly with hoverAuditBlind if
   it ever reads zero rules. A check that finds nothing and says clean is
   worse than no check.
2. serve.js sent Cache-Control: no-cache, which still lets the browser keep a
   copy. Now no-store, must-revalidate - a dev server serving a stale
   stylesheet costs an hour of debugging a fix that is already on disk.

The audit is proved: re-injecting
`html body .hero-actions a.btn-primary:hover{color:var(--gold)}` makes it
report exactly `اقرأ قصتي:var(--void)->var(--gold)`, and it reads 272 rules on
a clean page.
