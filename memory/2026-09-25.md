### Name typography decisions (2026-09-25, after the trilingual build)
- **Russian hero name is deliberately stacked** — Hussein asked for it:
  `Хусейн` over `Эль-Басьюни`, both flush to the same edge. Mechanism:
  `brand.nameLines` carries a real `\n` for `ru`, and `.hero-name` has
  `white-space: pre-line`. Arabic stays one line; English wraps on the
  space and lands flush too. Measured with `Range.getClientRects()` —
  both lines at the same x.
- **Header/footer brand name is `white-space: nowrap` in every language.**
  Before that, EN/RU wrapped onto 2–3 lines inside the header because the
  full desktop nav (7 links) + the lang switcher leave the brand only
  ~120px. The desktop row measures ~1035px of content, so the hamburger
  breakpoint was raised **760px → 1100px** (`.brand-name` gets `nowrap`
  plus the mobile treatment inside that query). Do not lower it without
  re-measuring brand + nav + switcher widths.
- **Switcher buttons stay `ع / EN / RU` in ALL modes** — Hussein approved
  this explicitly when asked (Latin-in-Arabic exception #2, now written
  into AGENTS.md). Language codes in their own script is the universal
  convention; do not localise them per mode.

### One-line rules + mobile header (2026-09-25, later the same evening)
Hussein: the quote line and the whole nav must sit on ONE line in every
language, "even though the Russian takes two lines".
- **`.hero-quote` and `.story-end` had `max-width: 34ch / 26ch`** — that
  cap (386px) was smaller than the natural line (ar 308 / en 416 /
  ru 414px), forcing two lines. Caps removed. Result: one line from
  ~520px up; below that it wraps because the text is physically wider
  than the viewport (at 360px the box is 297px — fitting 414px of text
  would need a ~12.6px font). Do NOT try to force it on phones.
- **Nav items wrapped INSIDE each link** (flex shrink on `.primary-nav a`),
  not the row itself. Fixed with `white-space: nowrap` + padding-inline
  12→8 + ul gap 8→6 + header gap 24→16 + `.lang-btn` 40→36.
- **Russian budget math** (do not re-derive blindly): row must fit in
  `shell(1120) - padding(48) - brand - switcher(120) - gaps(32)` ≈ 700px;
  RU needed 842px → the RU nav label was shortened
  `Обучение и сертификаты` → **`Обучение`** (i18n key `nav.learning`).
  Hamburger breakpoint raised 1100 → **1140px**, because the desktop row
  only fits at ≥1135px (shell is capped at 1120).
- **Three pre-existing bugs found while measuring (all fixed):**
  1. `.skip-link` used `inset-inline-start:50%` + `translateX(50%)` → in
     LTR it stuck out ~70px past the viewport (the whole 71px overflow in
     RU@360). Now `left:50%; translateX(-50%)`, direction-independent.
  2. `.records` was a plain grid: the track grew to the min-content of
     the widest card (long Russian words) and stuck out. Now
     `minmax(0,1fr)` on `.records` and `.record`.
  3. At 360px the hamburger was squished to **21px** (designed 44px) in
     EVERY language — nobody had measured it. Cause: name+switcher don't
     fit; fixed by the rule below.
- **Decision (Hussein's answer): below 470px the header hides the NAME
  text** and keeps the orbit mark + language switcher + hamburger. The
  name is still the giant h1 in the hero and the first line of the
  footer. The `.brand` anchor now carries `data-i18n-aria="brand.name"`
  so it is never left without an accessible name.

  measures quote/end line counts, nav rows, wrapped links, header/record
  overflow, hamburger width). **Deleted after use** — rebuild the same
